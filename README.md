# Closer

> Click any image to view it full size. Closer knows which images are worth opening.

点任意一张图，按原尺寸看清它。一个知道哪些图值得打开的 Chrome 扩展。

状态：**v0.1 功能齐了**。判断器、让位检测、字节通道、视图层、复制与保存全部落地，静态验收与冒烟测试通过。剩下的是真机站点回归与性能实测。

## 已经能跑的东西

| 命令 | 它验证什么 |
| --- | --- |
| `npm run verify` | 一条命令跑完四件事：manifest 引用完整性、权限白名单与体积预算、每个发布文件的语法、判断器 19 条规则 |
| `node tools/lab/e4-overlay.mjs` | 真浏览器里点开、滚轮缩放、`Esc` 关闭，并确认关闭后页面 DOM 逐字节还原（10 项） |
| `node tools/lab/e2-drift.mjs` | 图片动的时候，命中点判据会不会脱靶（480 次比对，0 漂移） |
| `node tools/lab/e3-pollution.mjs` | 跨域图经 blob 中转后 canvas 还污不污染（不污染，复制可做） |

`verify` 无需浏览器。其余三个需要本机有一个开着 `--remote-debugging-port=9333` 的 Chrome（E3 自带页面，E4 自带页面）。

## 为什么这不只是又一个看图插件

Chrome 自带一个看图器。十几个扩展各有一个，其中已经有一个把尺寸、EXIF、旋转做得很好。做第十五个，不成其为产品。

真正缺的是**判断力**：在一个 Closer 从没见过的页面上、面对四十张图，知道用户点下去的是哪一张。overlay 是容易的那一半，也是唯一能被抄走的那一半。判断器才是值得做的那一半——所以整个项目的其余部分，都是为保护它而写的。

## 一段话总结

全站默认开启，按站点关闭。点一张图，它从自己的缩略图里飞出来、就地展开，滚轮缩放、拖拽平移。左上角一个 ⓘ，点开才知道这张图到底是什么——原始像素尺寸与页面实际绘制的尺寸之差、宽高比、百万像素、格式、文件大小；右上角三个动作：复制、保存、关闭。不带查看器的站点，我们打开；自带查看器的站点，我们退场。除读取你正在看的那张图之外不发起任何网络请求，不申请 `downloads`，也不申请任何 host 权限——直到你按下那个按钮。无埋点、无构建步骤、无框架。
