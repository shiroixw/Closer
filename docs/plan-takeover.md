## 0. 一句话目标

> **用户能说出这一站归谁；说出来之后，它就一直是那样。**

今天的默认值做不到这件事：`自动` 会在两种相反的行为之间**逐次**切换（页面有查看器就让、没有就接管），而"页面有没有查看器"是用户点下去之前无法观测的事实。这不是判据算得准不准的问题，是默认值本身要求用户在不知情的情况下赌一次。

本方案不废除让位，而是**把让位从「不可关闭」收窄为「可按站点关闭」**，并补上接管之后必须具备的能力。

## 1. 状态模型

### 1.1 两条正交的轴

| 轴 | 取值 | 谁能改 | 存哪 |
|---|---|---|---|
| **会话** | `open` / `idle` | `Esc`、点背板、✕、图加载失败 | 内存 |
| **站点模式** | `自动` / `接管` / `暂停` | **只有用户显式动作** | `chrome.storage.local` |

**关闭动作不改变策略。** 接管态下按 `Esc` 只关这一张图，下一次点击仍然归我们。

### 1.2 三态的真实含义

| | 页面有自己的查看器 | 页面没有查看器 |
|---|---|---|
| **自动**（默认） | 页面开（我们让位） | **我们开** |
| **暂停** | 页面开 | **什么都不发生** |
| **接管** | **我们开**（拦掉页面） | 我们开 |

即：`自动` 不是第三种策略，而是**逐次在 `暂停` 与 `接管` 之间自动选择**。让位检测就是"这一帧自动选择让"。

### 1.3 "让位"是运行时事实，不是状态

D43 之后，让位不再有任何持久状态（`state.shell` / `state.yielded` 已删），`shelled()` 每次读的是**此刻的顶层**。所以 popup 里那行解释需要一个新的**只在会话内**的事实来源：

```js
// boot.js，让位分支里落一笔；刷新即清，不进 storage
if (Closer.shelled(img)) { Closer.state.lastYield = true; return; }
```

popup 副行 `本页：已让位给页面自己的查看器` 读的就是它。它**不是第四个选项**，不进配置、不跨页、不影响任何判断——只是把"刚才那一下为什么没开"变成可查询的。

页面未注入（未授权、刚刷新、`chrome://` 页）时必须显示 `未知`，不能默认成"没让位"。

### 1.4 三条硬约束

1. `Esc` 只碰会话轴。
2. 站点模式只由显式动作改变（popup 三态、面板那一行）。
3. 接管态下**禁用**"快速关闭 → 询问是否暂停"（§5.3）：用户刚按下接管，一次 `Esc` 就被反问，是在质疑他两秒前的决定。

## 2. 判据不动

`judge()` 的 14 条判据**一条不改**（第 1–13 条是否决，第 14 条是默认打开）。本方案只改"这次点击归谁"，不改"这张图值不值得打开"。

由此保留的边界（接管态仍然不开的图）：

- 控件里的图（按钮图标）、`a[download]`、链接包着的图
- `cursor` 为 pointer 语义的区域
- 图集库声明 / 已在对话框里
- 负 `z-index` 的背景层、全宽找回的版面底图

理由：这些形态的误判**不可逆**（导航、表单、下载、页面点击被吃掉），而 `cases.md` 13 条里 10 条属于这一类。接管改的是"页面查看器 vs 我们"的归属，不是这些边界。

## 3. 接管的技术实现

### 3.1 拦截点

`src/content/boot.js` 的 `onClick`，在 `judge()` 通过之后、`snapshot()` 之前：

```
现顺序：pick → judge → shelled → hint.reset → snapshot → preventDefault → rAF 比对
接管态：pick → judge → [只查 unseen / 全屏] → stopImmediatePropagation + preventDefault → open
```

- `document_start` 注入 + `window` capture，注册早于页面 inline script ⇒ 页面挂在 `click` 上的处理器（iWiki/tdesign、知乎、Pexels、km 的 `window.open`）**不会执行**。
- capture 阶段 `stopImmediatePropagation()` 同时阻断 target 阶段的 `onclick` 内联属性。
- **只拦 `click`**。不碰 `pointerdown` / `mouseover` / `wheel` —— 拦这些等于接管页面的每一次指针事件，属于"全接管"，本方案明确不做。

### 3.2 拦不住的部分（必须承认）

| 形态 | 结果 |
|---|---|
| 页面在 `pointerdown` / `mousedown` 里挂载查看器 | 我们先开、页面也开 → 双开 |
| `mouseover` 驱动的 hover 预览 | 同上 |
| 键盘 / 右键打开 | 我们不参与，页面自己开 |
| 纯 CSS `:hover` 反应 | 拦不到，但与查看器无关 |

经验估计 `click` 型查看器占 70–85%。

### 3.3 失败兜底：快退 + 自动降级

接管态下，`open()` 之后补一次早退检查（现在是 600 / 1200 ms 的迟到纠正，接管态改成 **下一帧 + 80 ms**）：

```
下一帧 / 80ms → covered(base) 命中（点击点被页面新挂的层盖住）
  → close(true)（不播退场动画）
  → 记一次失败；同一站点连续 2 次失败
      → 站点模式自动降级回「自动」，popup 与面板各提示一次：
        「这一站拦不住页面，已恢复让位」
```

降级理由：能解释（同一个站点两次没拦住）、可撤销（用户可再点接管）、不静默（有提示）。这与 D28 否决过的"静默整站失效"不同——那个是**推断**（页面动过一次就整站黑名单），这里是**观测 + 用户可见的降级**。

### 3.4 与 `yield.js` 的关系：只让一半

D43 之后 `shelled()` 是两件事拼起来的：

```js
Closer.shelled = (img) =>
  document.fullscreenElement || Closer.state.unseen || onTopLayer(img);
```

接管态**只能跳过 `onTopLayer` 那一半**：

| 判据 | 接管态 | 原因 |
|---|---|---|
| `onTopLayer(img)`（页面自己的查看层） | **跳过** | 这正是用户要接管的 |
| `state.unseen`（宿主被页面藏掉，cases 013） | **保留** | 不保留就会重复"开着却看不见、滚轮照吞"的卡死 |
| `document.fullscreenElement` | **保留** | 全屏时我们开了也看不见 |

落地方式：`shelled()` 拆成 `onTopLayer(img)` 与 `blind()` 两个导出，`boot.js` 按站点模式决定是否查前者。**默认态行为一字不变**，`e6` / `e10` / `test-yield` 的既有断言直接复用，无需重写。

## 4. 接管之后必须补齐的能力（门禁）

> 接管的前提不是"我们更好"，是"我们**不比对方少**"。现在少的那一项恰好最常见。

| 能力 | 现状 | 门禁级别 |
|---|---|---|
| 单图 FLIP 展开、`Esc`、DOM 逐字节还原 | ✅ | — |
| 滚轮/双击缩放、拖拽、`0/1/F/R/B` | ✅ | — |
| 真实尺寸 / 绘制尺寸 / 格式 / 体积 / 比例 | ✅ | 替换对方的第一理由 |
| 复制 / 保存 / `⌘C` `⌘S` | ✅ | 同上 |
| **图集漫游 `←` `→` + 预加载** | ❌ | **P0 硬门槛**（O2） |
| 大图加载态 / 失败态 | ⚠️ 只有 `error → close` | P1 |
| 触屏手势 | ❌ | 可选，接管移动端前才需要 |
| 视频 / 标注 / 对比 / 缩略图条 / 云 | ❌ | **永远不做**（宪法非目标） |

**因此实施顺序是：先 O2，再接管。** 反过来做，等于用"更好的单图查看器"替换掉"能翻页的查看器"，在用户最需要 Closer 的图集站上表现为退步。

## 5. 交互规格

### 5.1 入口（三处，都不新增界面元素）

| 位置 | 形态 | 说明 |
|---|---|---|
| popup | `这一站` + 三态 `seg`（自动 / 接管 / 暂停） | 复用现成的 `.seg` 样式，**零新增 CSS** |
| ⓘ 面板底部那一行 | 自动态：`在此站点暂停`<br>接管态：`交还页面` | 一行，随模式换文案与动作 |
| `⌥` + 点击 | 按次强制：跳过让位、只开这一张 | 不改站点模式；`judge()` 仍须通过 |

**`交还页面` ≠ `暂停`**：前者回到 `自动`（让位恢复），后者是彻底不参与。接管态下用户想退出，八成想的是前者。

### 5.2 图集漫游（O2）

- **数据源**：以被点图的共同容器为界收集 `<img>`（复用 `sameFrame()` 的口径），过滤 `judge()` 通过、已解码、URL 去重，按 DOM 顺序排序，上限 60 张。不跨容器，避免把整页广告算进来。
- **键位**：`←` `→` 翻页；滚轮**继续只缩放**，不翻页（避免与缩放抢手势）；到边界停住，不循环。
- **计数**：`3 / 12` 显示在底部中央，随 chrome 一起 2.2 s 淡出（复用 `bar.idle` 机制），不新增常驻元素。
- **过渡**：140 ms 淡出 → 换 `src` → 淡入。不做位置 FLIP（下一张在页面里可能不可见，起点无从取）。
- **状态**：换图必须 `token += 1`（现有机制），面板数据重算。

### 5.3 与"快速关闭询问"的关系（D45 的适用范围）

| 站点模式 | 快速关闭（< 800 ms、无交互）的含义 | 是否询问暂停 |
|---|---|---|
| 自动 | "我不想要这个"（未表态的默认被否掉） | ✅ 问一次 |
| **接管** | **"我看完了"** | ❌ 不问 |
| 暂停 | 不可能发生（我们不出场） | — |

### 5.4 接管态的可见性

popup 主行显示三态；副行在自动态且 `state.lastYield` 为真时显示 `本页：已让位给页面自己的查看器`。这是"不可预测的事只要能查询就变成可解释"的全部实现，不做常驻提示。

## 9. 决策与宪法影响（编号按当前 `decisions.md` 顺延）

按第十条，本方案落地时**必须**留下这些痕迹，否则就是沉默的违反。

### 9.1 新增决策（尚未做出）

| # | 决策 | 代价 |
|---|---|---|
| **D44** | 让位从「不可关闭」收窄为「默认可按站点关闭」。`接管` 是用户显式选择，`stopImmediatePropagation()` 只拦 `click`，`unseen` 与全屏仍生效。 | 接管态局部推翻第三条（页面主权）：页面收不到这一次点击。可解释（用户自己按的）、可撤销（交还页面）、不跨站。 |
| **D45** | 可逆类误判不修判据，交给"快速关闭 + 一次确认暂停"收敛；该机制**只对自动态生效**。 | 每个站点最多一次额外询问；接管态不触发。 |
| **D46** | 图集漫游（O2）从 v0.2 提前为接管的前置依赖，并独立成 `src/content/gallery.js`。 | 接管上线时间取决于 O2；反之 O2 单独也有价值。 |

### 9.2 宪法修正（与 D44–D46 同批落地）

| 条 | 改动 |
|---|---|
| 第一条 | 补**检验三（可陈述性）**：「用户能不能用一句话说出它什么时候会打开？」——现在的默认值答不出来，这正是本方案的起点。 |
| 第二条 | 适用范围加一句：接管态是用户显式选择，此时「宁可不打扰」让位于「按用户要求执行」，但判据的不可逆类边界不放开。 |
| 第六条 | 单文件上限（总量一半）进入方案约束：新功能优先新建文件，而不是往 `overlay.js` 里塞。 |
| 非目标 | 明确：视频帧、标注、对比、缩略图条、跨容器收集、循环翻页、手势翻页（移动端）。「强大」的收口是**不弱于主流站点查看器**，不是功能对标。 |

### 9.3 不做的事（写下来，免得下一轮再讨论）

- **全局强制接管**：判据全放开会让 10 条不可逆 bad case 回归；`stopImmediatePropagation` 全量施加会让"带图的按钮"一起失灵。
- **白名单（默认不接管）**：启用时机（事前）与需求时机（事中、随机）错配，装完等于没反应。
- **站点级自动黑名单**（D28 已否决）：保留否决；D45 的信号源是用户动作而非页面观测。

## 11. 风险与回退

| 风险 | 兜底 |
|---|---|
| 页面在 `pointerdown` 里挂载 → 双开 | 100 ms 内快退；同站 2 次失败自动降级 |
| 接管后页面按钮失灵（按钮里有 `<img>`） | `judge()` 第 6 条仍拦控件内的图；仍有「交还页面」一键退出 |
| 图集站体验不如页面自带 | O2 先落；接管默认关，用户显式开启 |
| 体积超 44 KB 或单文件超 22 KB | 新建 `gallery.js`；超了按 §7 顺序砍，不砍注释 |
| 用户忘记自己开过接管 | popup 常显三态；接管态下 ⓘ 面板那行写「交还页面」 |

**回退粒度**：`接管` 是 storage 里的一个站点列表，删掉即回到今天的行为；代码层面三态读取处一个 `if`，revert 一个 commit 即可。
